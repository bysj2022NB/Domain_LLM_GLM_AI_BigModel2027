## 一、系统概述

域盾是一套面向本地或单机部署的恶意域名辅助检测系统。系统以域名字符串为分析对象，使用机器学习识别 DGA（Domain Generation Algorithm，域名生成算法）相关风险，并通过大语言模型对检测证据进行独立复核，将模型预测、特征说明、AI 分析与历史记录整合到中文安全控制台中。

系统形成了“数据集检查与版本管理 → 模型训练 → 模型评测 → 人工发布 → 域名检测 → AI 复核 → 结果查询与导出”的完整业务流程。管理员可以管理数据、算法模型与 LLM 接口，普通用户可以输入域名或上传文件，获取可阅读、可追溯的检测报告。

## 二、建设目标与解决的问题

1. **降低模型使用门槛。** 将数据处理、训练、评测和发布放入可视化页面，使用者无需逐次编写训练脚本。
2. **提升检测结果的可读性。** 除类别与概率外，展示字符特征、判定依据、误判因素和核查建议，帮助使用者理解结果。
3. **支持实际的批量处理流程。** 处理文件编码、域名列选择、无效行和重复行，支持结果检索、分页、复核与导出。
4. **提高执行过程的透明度。** 长任务具有状态、进度、日志和失败原因，页面刷新后可恢复任务状态。
5. **保留结果追溯依据。** 检测记录关联模型版本与阈值，AI 复核独立保存，便于回看和比较。

## 三、系统创新点与设计亮点

以下创新点主要体现在系统集成、流程设计和工程实现，不主张提出了新的机器学习算法，也不声称优于所有现有检测方案。

### 3.1 机器学习检测与 LLM 独立复核相结合

机器学习完成域名风险分类，LLM 基于已有域名特征、预测结果和相关证据补充中文分析。两种结果分开保存，AI 可以表达赞同、分歧或不确定，不覆盖机器学习原始判断，也不自动成为新的训练标签。

这种设计将自动分类与人工可阅读的辅助分析连接起来，使用户能够同时查看模型判断和另一层解释，而不是只接收一个标签。

### 3.2 从数据到报告的版本化流程

系统不仅提供预测接口，还管理数据集版本、训练参数、模型产物、评测记录及发布状态。每次检测固定所使用的模型版本，后续修改默认模型或发布状态不会改变已提交任务的模型选择。历史记录保留必要的模型与结果快照。

### 3.3 重视数据质量和跨集合泄漏控制

数据处理包含规范化、去重、格式校验和正负标签冲突隔离；训练、验证和测试按可注册域名分组划分，避免同组域名跨集合。缩放、概率校准与阈值选择不接触测试集，使算法比较更有依据。

### 3.4 可配置的多 LLM 接口故障转移

管理员可以配置多个兼容 OpenAI Chat Completions 的接口并调整访问顺序。调用遇到超时、网络或接口错误、空响应、报告解析失败时，系统按顺序尝试后续接口。页面展示“未测试、可用、不可用”状态，并在配置卡片内反馈测试中的 loading 状态。

### 3.5 兼顾证据说明与交互反馈

基础检测报告无需 LLM 即可生成，结合实际字符特征和训练数据的统计参照解释风险线索。AI 复核提供进度与阶段文字提示，训练提供日志与任务状态；这些反馈表示执行过程，不等同于展示大模型内部思维链。

### 3.6 六维可视化安全工作台

工作台使用 ECharts 展示检测趋势、风险分布、概率分布、模型使用量、AI 复核状态和后台任务状态。每张图注明统计口径，并提供可展开的数据表，兼顾直观浏览与具体数值查看。

## 四、应用场景

| 场景 | 使用方式 | 应用价值 |
|---|---|---|
| 课题研究与项目答辩 | 演示训练、评测、发布、检测和 AI 复核流程 | 展示完整的软件工程与机器学习应用能力 |
| 网络安全教学 | 比较随机森林、线性 SVM 与逻辑回归，查看误判样本 | 理解特征、阈值、指标与误报之间的关系 |
| 域名清单初步筛查 | 将已有域名清单整理为 TXT/CSV 后批量上传 | 从大量域名中寻找需要进一步检查的风险线索 |
| 算法实验与模型比较 | 在固定数据划分上训练不同模型并查看评测记录 | 为参数选择和算法分析提供可追溯依据 |
| 安全分析辅助报告 | 对选中记录进行 AI 复核，导出结果 | 整理检测依据、分歧与后续核查建议 |

系统适合作为辅助筛查工具。真实业务中的处置仍需结合访问行为、业务背景及其他证据；当前系统不会主动采集这些外部信息。

## 五、系统核心功能

### 5.1 账户与权限管理

系统支持注册、账户密码登录、手机短信验证码登录、退出和修改密码。用户先通过当前密码与短信验证码绑定手机号，随后可在登录页通过短信验证重置密码；重置后旧登录会话失效。注册账户固定为普通用户，管理员可以管理用户状态、重置密码和调整角色。

普通用户只能访问自己的检测、复核、任务与导出记录；管理员可以访问全系统记录，并使用数据集管理、训练、评测、模型管理和 LLM 配置等管理功能。权限在服务端执行，页面隐藏只是交互层面的辅助。

### 5.2 安全工作台

工作台展示有效域名预测数、预测恶意数量、已完成 AI 复核数、已发布模型数量、Worker 状态与最近检测任务，并提供快速域名检测入口。

| 图表 | 展示内容与口径 |
|---|---|
| 近 14 天检测趋势 | 按上海时区统计每日正常、恶意预测数量，缺失日期补零 |
| 检测风险分布 | 全部可见预测中正常与恶意的数量和占比 |
| 恶意类别概率分布 | 按五个概率区间统计数量，最后一个区间包含 100% |
| 模型使用量 TOP 8 | 按模型处理的预测记录数排序，包含历史模型 |
| AI 复核状态 | 按复核记录统计各状态，重复复核分别计数 |
| 后台任务状态 | 汇总用户有权查看的任务状态 |

预测数量在批次内去重，跨批次分别计数。普通用户查看本人业务统计，管理员查看全系统统计；已发布模型数量反映可用的公共检测模型。支持手动刷新、空数据提示及窄屏单列布局。

### 5.3 数据集管理

数据集管理独立于训练中心，支持检查本地 `dataset/` 数据、查看版本与质量报告、选择版本用于训练，以及按引用约束删除版本。

现有原始数据包括 `all_dga.txt` 和 `all_legit.txt`，原始行数分别为 801,667 和 1,000,000。标签 0 映射为正常，1～8 映射为恶意；保留原始标签用于统计，不把数字解释成具体恶意家族。

数据处理统一大小写、尾随点和 IDNA 表示，记录无效输入与重复项，隔离正常/恶意标签冲突。原始文件保持只读，清洗报告和划分文件写入 `runtime/`。最终可用数量以对应版本质量报告为准。

当前数据集管理检查本地训练文件；域名检测中的上传文件用于预测，不会自动加入训练集。

### 5.4 模型训练

系统提供三种可选择的算法：

| 算法 | 实现方式 | 使用特点 |
|---|---|---|
| 随机森林 | RandomForestClassifier，基于域名统计特征 | 作为默认训练算法，支持树批次进展反馈 |
| 线性 SVM | StandardScaler + LinearSVC，独立概率校准 | 适合进行线性分类模型比较，避免全量核 SVM 的高训练开销 |
| 逻辑回归 | StandardScaler + LogisticRegression | 作为结构清晰的对照模型 |

特征包含域名长度、主体长度、层级数、字符熵、数字和元音比例、连字符比例、不同字符数量及连续字符长度等。系统将特征模式、预处理器、分类器、校准器、阈值和版本信息一起保存。

默认快速模式从固定训练集中按类别比例抽取最多 20 万条样本，管理员也可选择全量训练。训练与评测在后台执行，页面提供状态、进度、日志和取消入口。

### 5.5 模型评测与生命周期管理

评测页提供 Accuracy、Precision、Recall、F1、ROC-AUC、PR-AUC、误报率、漏报率和推理耗时，并通过混淆矩阵、ROC 曲线及 PR 曲线展示模型表现。误判样本每页展示六条，历史评测记录支持查看和按约束删除。

模型完成有效评测后，由管理员人工发布。系统允许多个模型同时发布，设置一个默认模型，用户可选择其他已发布模型。管理操作包括发布、取消发布、设为默认和删除；已发布或被运行任务使用的模型不能直接删除。

实际指标以当前评测报告为准。当前系统不承诺固定准确率，也不把某次测试集成绩当作所有业务场景的表现。

### 5.6 单域名与批量文件检测

单域名检测输入一个域名后，直接在当前页面展示结果卡及完整报告说明，不显示批量域名选择列表。

批量检测支持 TXT、CSV，默认限制 20 MB、10 万行。TXT 支持每行一个域名，也兼容“域名 标签”格式；附带标签不参与预测。CSV 支持预览和选择域名列，提供 UTF-8、UTF-8 BOM 与 GB18030 编码处理。

有效行继续检测，无效行单独说明原因；重复域名只推理一次，保留来源行与重复关系。批量结果采用域名列表与报告区域组合，用户可自由切换查看任意记录。开始新检测或切换检测方式时清空旧的页面结果，历史记录仍然保留。

### 5.7 检测报告、历史查询与导出

基础报告包括预测类别、恶意类别概率、阈值、模型版本、实际域名特征、统计参照、可能误判因素、证据限制和核查建议。统计特征说明属于风险线索说明，不冒充模型的因果解释。

独立检测结果页按全部可见记录分页展示，提供域名、判断和 AI 状态筛选；表头全选框选择当前页，支持勾选删除，以及 CSV、JSON 导出。记录归属与删除限制由后端校验。

### 5.8 LLM 配置与 AI 复核

通过 LangChain 的 ChatOpenAI 接入兼容接口。管理员可以添加、编辑、删除配置，设置 Base URL、模型标识、API Key、超时、输出长度和启用状态，并通过上移、下移调整顺序。

用户在检测结果中主动点击 AI 复核，可以单条复核，也可在结果页选择最多 20 条记录复核。页面提供执行进度与阶段说明，完成后展示结论、依据、与机器学习判断的分歧、局限性和建议。所有接口失败时保留原始机器学习结果并展示失败原因。

AI 仅分析已提供的证据，不查询 DNS、WHOIS、网站内容或外部威胁情报。密钥加密保存在 SQLite 中，加密密钥单独存放于 `runtime/secrets/`。

### 5.9 任务、日志与运行管理

采用 Flask API 与独立 Worker，任务状态持久化到 SQLite。训练、评测共享重任务执行资源，检测与 AI 请求使用有界资源。前端轮询进度和增量日志，可计数阶段显示实际比例，难以精确计数的阶段通过状态与耗时反馈。

支持任务取消、失败重试与中断识别，避免进程退出后一直显示运行中。后端请求日志可以在控制台查看，日志和模型产物统一写入 `runtime/`。运行 `项目代码/backend/run.py` 可以启动后端 API 与 Worker。

## 六、技术栈与系统架构

| 层次 | 当前技术 | 用途 |
|---|---|---|
| 前端应用 | Vue 3、TypeScript、Vite | 页面开发、类型检查与构建 |
| 路由与状态 | Vue Router、Pinia | 页面导航、登录与应用状态 |
| 界面组件 | Element Plus、自定义 HTML/CSS 组件 | 表单、交互与蓝黑控制台界面 |
| 可视化 | ECharts | 工作台和模型评测图表 |
| 后端 | Python 3.13、Flask、Waitress | REST API 与单机服务托管 |
| 数据访问 | SQLAlchemy、Flask-SQLAlchemy、Alembic | 数据模型、事务及迁移 |
| 数据库 | SQLite，DELETE 日志模式 | 用户、模型元数据、任务、检测与复核记录 |
| 机器学习 | scikit-learn、NumPy、pandas、joblib | 数据处理、训练、评测和模型保存 |
| 域名处理 | idna、tldextract、本地公共后缀规则 | 规范化、后缀解析与分组 |
| LLM 接入 | LangChain、langchain-openai、Pydantic | 兼容 API 调用、故障转移与报告校验 |
| 安全与测试 | cryptography、Werkzeug、pytest、Playwright | 密钥保护、密码哈希、接口与浏览器测试 |

浏览器访问 Vue 应用，应用向 Flask API 提交请求。普通查询直接返回，训练、检测、评测与 AI 复核等耗时工作提交为后台任务，由 Worker 执行。数据库保存结构化记录，文件系统保存模型、数据划分和大报告，前端查询任务状态并更新页面。

正式构建后的前端由 Flask 同源托管；本地机器学习流程不依赖 GPU、Redis 或云端训练服务。AI 复核需要配置可访问的兼容接口，其可用性取决于对应供应商或本地模型服务。

## 八、应用价值与后续扩展方向

系统将数据质量管理、模型实验、业务检测、AI 辅助分析和运行反馈放入同一应用，为教学演示与域名风险筛查提供完整流程。其价值在于让分类结果可读、执行过程可见、历史依据可查。

后续可以考虑增加时间外与未知家族数据评测、更多特征与算法、外部情报查询、审批处置流程或更大规模任务调度。这些属于后续方向，当前版本尚未实现。系统现有能力与边界应以实际页面、接口和评测报告为准。
